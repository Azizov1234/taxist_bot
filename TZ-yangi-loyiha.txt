================================================================================
LOYIHA NIMA QILADI (MAQSAD)
================================================================================

Telegram guruhlarida odamlar "taksi kerak, Toshkentdan Guliston" deb
yozadi. Shu xabarlarni bot avtomatik ko'rib, haqiqiy so'rovni ajratib,
haydovchilar guruhiga/kanaliga yuboradi.

Muammo:
  - Yo'lovchi guruhda 500+ xabar/kun keladi
  - Ularning 80% keraksiz: reklama, haydovchi o'z tavsifi, spam
  - Haydovchilar hamma xabarni ko'rib o'tirishi vaqt oladi

Yechim:
  - Bot/userbot yo'lovchi guruhini kuzatadi
  - Har xabarni tahlil qiladi (rule-based + AI)
  - Faqat haqiqiy "taksi kerak" xabarlarni haydovchi guruhiga yuboradi
  - Keraksiz xabarlarni guruhdan o'chiradi (admin bo'lsa)

   Nima qiladi:
     - Oddiy Telegram bot token bilan ishlaydi

   npm install @prisma/client
   npm install -D prisma
   Nima qiladi:
     - PostgreSQL bilan ishlash
     - Avtomatik type generation

     - Xabarlarni, keywordlarni, adminlarni, loglarni DB ga yozish

   Nima qiladi:

5. ENV YUKLASH — "dotenv"
   npm install dotenv
   Nima qiladi:
     - .env faylini process.env ga yuklaydi

6. LOGGER — "pino" + "pino-pretty"
   npm install pino
   npm install -D pino-pretty
   Nima qiladi:

================================================================================
MA'LUMOTLAR BAZASI — POSTGRESQL
================================================================================

Nima saqlash kerak (jadvallar):

1. Lead (yo'lovchi so'rovlari):
   - sourceMessageId    : Telegram guruhda xabar ID
   - sourceChatId       : Qaysi guruhdan keldi
   - senderId/fullName  : Kim yozdi
   - originalText       : Asl xabar
   - normalizedText     : Normalize qilingan xabar
   - fromLocation       : Qayerdan (Toshkent)
   - toLocation         : Qayerga (Guliston)
   - phone              : Telefon raqam (agar bo'lsa)
   - status             : NEW / SENT / IGNORED / DUPLICATE / ERROR
   - driverMessageId    : Haydovchi guruhida yuborilgan xabar ID
   - createdAt          : Qachon

2. KeywordDictionary (kalit so'zlar lug'ati):
   - phrase             : "taksi kerak"
   - normalized         : "taksi kera" (normalize qilingan)
   - category           : PASSENGER / DRIVER / CARGO / SPAM / AMBIGUOUS
   - weight             : Og'irlik (1-10)
   - matchType          : EXACT / PHRASE / REGEX

3. AdminUser (adminlar):
   - telegramId         : Telegram ID
   - username           : @username
   - role               : SUPERADMIN / ADMIN

4. RuntimeConfig (dinamik sozlamalar, key-value):
   - Guruh qo'shish, o'chirish sozlamalari
   - on/off kalitlari

5. BotLog (tizim loglari):
   - level              : INFO / WARN / ERROR
   - message            : Log matni
   - meta               : JSON qo'shimcha

ASOSIY JARAYON — NIMA YOZILISHI KERAK

BOSQICH 1: SOZLASH (config)

BOSQICH 2: MA'LUMOTLAR BAZASI (prisma)
  Yozish kerak:
    - prisma/schema.prisma — Lead, Keyword, Admin, RuntimeConfig, BotLog
    - src/prisma/client.ts — singleton Prisma client
    - prisma/seed.ts — boshlang'ich keyword va admin ma'lumotlar

BOSQICH 3: USERBOT (GramJS)
  Yozish kerak:
    - src/userbot/client.ts
        * my.telegram.org API ID/HASH bilan ulanish
        * Birinchi marta: telefon, kod, 2FA so'rash
        * Session ni fayl/DB ga saqlash
        * Qayta ulanishda session dan foydalanish
        * Reconnect: avtomatik qayta ulanish
    - src/userbot/listener.ts
        * PASSENGER_CHAT_IDS guruhlarini tinglash
        * Har yangi xabar uchun lead.service ga yuborish

BOSQICH 4: KLASSIFIKATSIYA (classifier)
  Yozish kerak:
    - src/utils/text.ts
        * normalizeUzbekText() — lotin/kirill bir xil ko'rinishga keltirish
        * hasSpamSignals() — oddiy spam belgilarini aniqlash
    - src/utils/route.ts
        * detectRoute() — "Toshkentdan Guliston" => {from, to}
    - src/utils/phone.ts
        * extractPhone() — matndan telefon raqam olish
    - src/services/keyword.service.ts
        * DB dagi keywordlar keshini xotiraga yuklash
        * Weighted scoring: PASSENGER vs DRIVER vs CARGO vs SPAM
    - src/services/classifier.service.ts
        * classifyMessage() — asosiy klassifikatsiya funksiyasi
        * Rule-based: keyword + regex
        * AI: faqat AMBIGUOUS holatda (OpenAI/Gemini/Groq)
        * AI xato bersa rule-based natijaga qaytish

BOSQICH 5: LEAD QAYTA ISHLASH (lead.service)
  Yozish kerak:
    - processIncomingMessage() — asosiy pipeline:
        1. Text bormi? skip
        2. Duplicate? skip
        3. Normalize
        4. Classify
        5. PASSENGER bo'lsa driver guruhga yuborish
        6. Source xabarni o'chirish (ruxsat bo'lsa)
        7. Yo'lovchiga lichka tasdiq (ixtiyoriy)
        8. DB ga yozish

BOSQICH 6: HAYDOVCHI KANALIGA YUBORISH (delivery.service)
  Yozish kerak:
    - sendToDriverChannel()
        * Bot orqali: Bot API (grammy)
        * Userbot orqali: GramJS
        * Auto: token bo'lsa bot, bo'lmasa userbot

BOSQICH 7: ADMIN BOSHQARUV (bot/admin.commands)
  Yozish kerak:
    - grammY bot ishga tushirish
    - Admin buyruqlari:
        /status   — bot holati
        /pause    — to'xtatish
        /resume   — davom ettirish
        /stats    — statistika
        /test     — xabarni test qilish
    - Admin tekshirish middleware — faqat DB dagi adminlar kiradi

BOSQICH 8: LOGGER (logger.service)
  Yozish kerak:
    - Pino logger wrapper
    - writeInfo(), writeWarn(), writeError()
    - DB ga ham log yozish (BotLog jadvali)

BOSQICH 9: ISHGA TUSHIRISH (main.ts)
  Yozish kerak:
    - DB ulanish

    - Adminlar upsert
    - Keyword kesh yuklash

    - Listener ishga tushirish

================================================================================
KLASSIFIKATSIYA QOIDALARI (RULE-BASED)
================================================================================

PASSENGER (yo'lovchi so'rovi) — shu xabar haydovchilarga yuboriladi:
  Kalit so'zlar:
    "taksi kerak", "mashina kerak", "taksi topib bering",
    "boraman", "ketaman", "chiqaman", "joy bormi",
    "nechi pul", "qancha turadi", "[shahar]dan [shahar]ga"

  Regex misollar:
    /taksi.{0,10}kerak/i
    /\d\s*kishi.{0,20}kerak/i
    /(boraman|ketaman|chiqaman).{0,30}(toshkent|guliston)/i

DRIVER (haydovchi reklamasi) — skip yoki o'chirish:
  Kalit so'zlar:
    "olib ketaman", "odam olaman", "yo'lovchi olaman",
    "mashina bor", "taksi bor", "kuzataman"

  Regex misollar:
    /\bolib\s*ketaman\b/i
    /\bodam\s*olaman\b/i

CARGO (pochta/yuk):
  "pochta bormi", "yuk bor", "jo'natish kerak"

SPAM:
  "aktsiya", "kredit", "cashback", "bonus",
  "kanalga obuna", "havola", reklama belgilari

AMBIGUOUS:
  Hech qaysi kategoriyaga ishonchli kirmasa => AI ga yuboriladi

AI INTEGRATSIYA (IXTIYORIY)

Qachon ishlatiladi:
  - Faqat AMBIGUOUS xabarlar uchun
  - AI_ENABLED=true bo'lganda

Provayderlar (AI_PROVIDER_ORDER tartibida):
  1. OpenAI (GPT-4o-mini, GPT-4o)
  2. Google Gemini (gemini-1.5-flash)
  3. Groq (llama-3.1-8b-instant)

  - Xabar matni beriladi
  - Kategoriya so'raladi: PASSENGER / DRIVER / CARGO / SPAM
  - JSON javob kutiladi: { category, confidence, from, to, phone }

Cooldown tizimi:
  - Bitta provider xato bersa 5 daqiqa o'chiriladi
  - Keyingi provayderga o'tiladi
  - Hammasi o'chsa rule-based natija ishlatiladi


================================================================================
BARQARORLIK SOZLAMALARI
================================================================================

GramJS sozlamalari:
  connectionRetries: -1      (cheksiz qayta ulanish)
  retryDelay: 2000           (2 soniyada qayta urinish)
  useWSS: true               (443 port, barqarorroq)

Startup backfill:
  - Restart bo'lganda so'nggi 3 daqiqa xabarlarni qayta tekshirish
  - Har guruhdan oxirgi 20 xabarni skanerlash

Heartbeat:
  - Har minutda Telegram ulanishini tekshirish
  - Xato ko'paysa PM2/systemd restart signal beradi

Instance lock:
  - Bir vaqtda faqat bitta instance
  - Lock fayl: /tmp/taxibot.lock
