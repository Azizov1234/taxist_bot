1. LOYIHA HAQIDA UMUMIY MA'LUMOT
================================================================================

Loyiha nomi   : Taxi Lead Bot
Maqsad        : Telegram guruhlarida yo'lovchilarning taksi so'rovlarini
                avtomatik aniqlash, filtrlash va tegishli haydovchilar
                guruhiga/kanaliga yuborish.

Muammo        : Taksi guruhlarida kuniga yuzlab xabar keladi — ularning
                ichida haqiqiy "taksi kerak" so'rovlari, haydovchi
                reklamalari, spam va boshqa keraksiz xabarlar aralashib
                ketadi. Haydovchilar hamma xabarni ko'rib o'tirishi shart
                emas — faqat haqiqiy yo'lovchi so'rovlari kerak.

Yechim        : Bot/userbot yo'lovchi guruhlarini kuzatib, har bir
                xabarni tahlil qiladi, haqiqiy taksi so'rovini aniqlab,
                haydovchi guruhiga formatlangan holda avtomatik yuboradi.

5. ASOSIY JARAYON (FLOW)
================================================================================

Startup:
  1. App ishga tushadi
  2. .env o'qiladi va Zod orqali validatsiya qilinadi
  3. Prisma DB ga ulanadi
  4. DB dan RuntimeConfig yuklanadi (admin panel sozlamalari)
  5. Default adminlar .env dan DB ga upsert qilinadi
  6. Default keywordlar DB ga upsert qilinadi
  7. KeywordDictionary keshi xotiraga yuklanadi
  8. GramJS userbot Telegram ga ulanadi (MTProto)
  9. Manba yo'lovchi guruhlar tekshiriladi (validatsiya)
  10. Userbot listener ishga tushadi

Har bir yangi xabar uchun:
  11. Manba guruhdan yangi xabar keldi
  12. Text/caption bormi? Yo'q => skip
  13. Haydovchi guruhidan kelganmi? => skip
  14. Xabar mavjudmi DB da (duplicate)? => skip
  15. Matn normalize qilinadi (lotin/kirill, ko'p bo'shliq, emojilar)
  16. Spam signallari tekshiriladi
  17. Rule-based classifier ishga tushadi:
        - KeywordDictionary bo'yicha (PASSENGER/DRIVER/CARGO/SPAM/AMBIGUOUS)
        - Regex patterlar (haydovchi reklamasi aniqlash)
        - Yo'nalish aniqlash (FROM => TO shahar/tuman)
        - Telefon raqam ajratish
  18. Natija AMBIGUOUS bo'lsa => AI analyzer (fallback bilan)
        - OpenAI / Gemini / Groq (AI_PROVIDER_ORDER bo'yicha)
        - AI xato bo'lsa => rule-based natijaga qaytish
  19. PASSENGER kategoriyami?
        Ha  => Haydovchi guruhiga yuborish
        Yo'q => IGNORED sifatida DB ga yozish
  20. Haydovchi guruhga formatlangan xabar yuboriladi
  21. Lead DB ga SENT statusida saqlanadi
  22. Manba xabar o'chirilsinmi? (DELETE_SOURCE_MESSAGE_IF_ADMIN=true)
        => Userbot admin bo'lsa o'chiradi
  23. Keraksiz xabar o'chirilsinmi? (DELETE_IGNORED_MESSAGE_IF_ADMIN=true)
        => IGNORED bo'lsa ham o'chiradi
  24. Yo'lovchiga lichkada tasdiq yuborilsinmi?
        (SEND_PRIVATE_ACK_TO_PASSENGER=true) => yuboriladi
  25. Har narsa DB ga log yoziladi

Restart barqarorligi:
  - LISTENER_BACKFILL_SECONDS=180: restart oldidan 3 daqiqa ichidagi
    xabarlarni qayta tekshiradi
  - LISTENER_STARTUP_BACKFILL_LIMIT=20: startup da har guruhdan oxirgi
    20 ta xabarni skanlaydi
  - LISTENER_PERIODIC_CATCH_UP_ENABLED=true: periodik polling —
    live event uzilib ketsa ham orqada qolgan xabarlarni ushlaydi

6. XABAR KLASSIFIKATSIYASI
================================================================================

Kategoriyalar:
  PASSENGER  — Yo'lovchi taksi so'radi => haydovchilarga yuboriladi
  DRIVER     — Haydovchi o'zini reklama qildi => o'chiriladi/skip
  CARGO      — Pochta/yuk jo'natish so'rovi
  SPAM       — Reklama, keraksiz xabar
  AMBIGUOUS  — Noaniq => AI ga beriladi

Klassifikator zanjirlari:

  1) KeywordDictionary tahlili:
     - DB dagi keywordlar keshi xotiraga yuklangan
     - Har bir keyword: phrase, normalized, category, weight,
       language, matchType (EXACT/PHRASE/REGEX), source
     - Weighted scoring: PASSENGER_SCORE vs DRIVER_SCORE vs CARGO_SCORE vs SPAM_SCORE
     - Yuqori score g'oliblikni aniqlaydi

  2) Regex pattern tahlili (haydovchi reklamasi aniqlash):
     - "olib ketaman/ketamiz"
     - "odam olaman/olamiz"
     - "yo'lovchi olaman"
     - "taksi + odam + kerak" kombinatsiyalari
     - "pochta/odam bo'lsa olamiz"
     - 10+ boshqa pattern

  3) Yo'nalish aniqlash (route detection):
     - From/To shahar/tuman nomlarini ajratadi
     - "Toshkentdan Guliston" => from: Toshkent, to: Guliston

  4) AI tahlili (faqat AMBIGUOUS holatda):
     - OpenAI (GPT modellari)
     - Google Gemini
     - Groq
     - Tartib AI_PROVIDER_ORDER bilan belgilanadi
     - Bitta provider xato bersa keyingisiga o'tadi (cooldown tizimi)
     - AI o'chiq bo'lsa (AI_ENABLED=false) faqat rule-based ishlaydi

7. MA'LUMOTLAR BAZASI MODELLARI (Prisma + PostgreSQL)
================================================================================

Model: Lead
  Maqsad: Har bir aniqlangan yo'lovchi so'rovini saqlash
  Maydonlar:
    - sourceChatId         : Qaysi guruhdan keldi
    - sourceMessageId      : Guruhda xabar ID
    - senderId / fullName  : Yuboruvchi ma'lumoti
    - originalText         : Asl xabar matni
    - normalizedText       : Normalize qilingan matn
    - fromLocation / toLocation : Yo'nalish
    - phone                : Telefon raqam
    - confidence           : AI ishonch darajasi (0-1)
    - isDriverAd / isSpam  : Haydovchi reklama yoki spam belgisi
    - status               : NEW / SENT / IGNORED / DUPLICATE / ERROR / ...
    - targetDriverChatId   : Qaysi haydovchi guruhga yuborildi
    - driverMessageId      : Haydovchi guruhidagi xabar ID

Model: KeywordDictionary
  Maqsad: Klassifikatsiya uchun kalit so'zlar lug'ati
  Maydonlar:
    - phrase      : Asl so'z/ibora
    - normalized  : Normalize qilingan varianti
    - category    : PASSENGER / DRIVER / CARGO / SPAM / AMBIGUOUS
    - weight      : Og'irlik (1-10)
    - language    : LATIN / CYRILLIC / RUSSIAN / MIXED
    - matchType   : EXACT / PHRASE / REGEX
    - source      : global yoki region nomi

Model: Keyword (Legacy)
  Maqsad: Eski sodda keyword ro'yxati

Model: RuntimeConfig
  Maqsad: Admin panel sozlamalarini DB da saqlash (key-value store)
  Misollar:
    - PASSENGER_GROUP_AUTO_REPLIES    : guruhga javob yozish on/off
    - SEND_PRIVATE_ACK_TO_PASSENGER   : lichkaga tasdiq on/off
    - DELETE_SOURCE_MESSAGE_IF_ADMIN  : manba xabar o'chirish on/off
    - DELETE_IGNORED_MESSAGE_IF_ADMIN : keraksiz xabar o'chirish on/off
    - qo'shilgan guruh ID lari, driver chat ID lari

Model: AdminUser
  Maqsad: Adminlar ro'yxati
  Maydonlar:
    - telegramId  : Telegram user ID
    - username    : @username
    - role        : SUPERADMIN / ADMIN
    - isActive    : Faol yoki bloklangan

Model: BotLog
  Maqsad: Tizim loglarini DB da saqlash
  Maydonlar:
    - level   : INFO / WARN / ERROR
    - message : Log xabari
    - meta    : JSON qo'shimcha ma'lumot

12. BARQARORLIK VA XATOLIKLARNI BOSHQARISH
================================================================================

Instance lock:
  - Bir vaqtda faqat bitta userbot instance ishlashi uchun lock fayl
  - /tmp/taxi-lead-bot.userbot.lock
  - Ikkinchi instance ishga tushsa xato beradi va to'xtaydi

Reconnect:
  - TELEGRAM_CONNECTION_RETRIES=-1  : ulanish xatolarida cheksiz qayta urinish
  - TELEGRAM_RECONNECT_RETRIES=-1   : reconnect cheksiz
  - TELEGRAM_RETRY_DELAY_MS=2000    : har 2 soniyada qayta urinish

Heartbeat:
  - USERBOT_HEARTBEAT_INTERVAL_MS=60000 : har minutda Telegram ulanish tekshiruvi
  - Ketma-ket xatolar ko'paysa process supervisor (PM2/systemd) restart qiladi

AI provider cooldown:
  - Bitta provider xato bersa vaqtincha o'chiriladi (cooldown)
  - Cooldown tugagach qayta ishlatiladi
  - Barcha provider ishlamasa rule-based natijaga qaytiladi

Polling konflikt:
  - Bir xil token bilan ikki instance bo'lsa 409 xato
  - Loglarda "terminated by other getUpdates" ko'rinadi
